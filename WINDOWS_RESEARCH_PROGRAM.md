# Native Windows branch research program and scope boundary

**Scope:** AMD Ryzen 7 9800X3D workstation, native x86-64 programs launched from the existing VS Code repository, one ordinary Windows user-mode security context. This is a staged investigation motivated by the [Fractal paper](https://people.csail.mit.edu/mengjia/data/2026.SP.fractal.pdf), especially its progression from a controlled single-threaded train/receiver test to comparisons between tasks and security domains. It does not run Fractal. The paper's evaluation used Apple M1, a cache-based receiver and controlled address-space and privilege arrangements; this repository primarily observes fenced TSC timing on x86 under a general-purpose OS and adds one indirect-target cache-reload pilot. The difference in endpoints and platforms is part of every interpretation.

## Decisions after the first new suite session

1. **Build or trace failure:** preserve the executable, log and transcript. Correct the implementation as a new version before another physical run. Do not count a failed attempt as a null result or silently replace it.
2. **Binary layout or small-control failure:** retain the data as an engineering pilot. Audit the physical instruction sequence and timer scale, then version a corrected protocol. No mechanism claim follows from a failed control.
3. **Valid controls, null primary contrasts:** publish the null estimates with uncertainty and exact conditions. Select a new hypothesis only if it addresses a documented limitation, and label it exploratory.
4. **Valid controls, stable exploratory contrast:** compare both outcomes and controls, select one falsifiable primary estimand in a new frozen protocol, and repeat unchanged on distinct dates. Cross-study timings have different units and different branch addresses, so do not pool them as one effect size.
5. **After independent replication:** write a claim ledger separating directly observed latencies from inferred hardware explanations. A scientifically useful result can be a reproducible bounded timing characterization even when it does not reveal the exact predictor circuit.

The [full-session guide](WINDOWS_MULTI_EXPERIMENT_SUITE.md) describes the pilot VS Code task, seven exploratory studies and follow-up rotation. Together these supply a bounded native single-process conditional and indirect branch program once the physical binaries, controls and independent sessions are audited. G is excluded from this version. H is a TSC-only indirect baseline; I adds a candidate cache receiver whose speculative interpretation depends on physical audits, controls and independent replication. Stage 6 is a different system-software and hardware research program, not an unfinished VS Code task that can be completed by increasing sample counts. No amount of these user-mode data alone establishes Fractal's M1 privilege-boundary result.
